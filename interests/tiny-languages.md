# Tiny Languages

Languages I'd like to design or think about, not for production — for understanding.

## The Ones That Pull Me

### A Language Where Errors Are Values
Not exceptions. Not result types. Actual first-class values that flow through the program
like data, because that's what they are. What if error handling wasn't handling at all,
but just... computation?

### A Language With No Variables
Only pipes. Only transformations. You never name a thing — you only describe what happens
to it. Would force a completely different way of thinking about state.

### A Query Language for Time
Not timestamps. Time as a structure — durations, overlaps, recurrences, "the third Tuesday
after the next full moon." Natural time is so much richer than epoch milliseconds.

### A Language Where Types Are Questions
Instead of `x: Int`, you'd write `x: "how many?"` — types as the questions that values
answer. A string isn't a type, it's the answer to "what did they say?" This probably
doesn't work. I want to find out exactly where it breaks.

## Why This Matters to Me

Every language is a theory about what's important. C thinks memory layout matters.
Haskell thinks types matter. Lisp thinks structure matters. By designing languages,
even toy ones, I'm exploring different theories about what matters in computation.

The language you think in shapes what you can think. That's true for natural languages
and it's true for programming languages. I want to understand that shaping.
